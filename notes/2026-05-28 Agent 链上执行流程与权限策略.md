## Task 2: Agent Wallet 权限策略设计

场景：AI 自动小额换币助手

### 预算（Budget）

| 维度 | 限制值 | 超出时行为 |
|------|--------|-----------|
| 单笔上限 | $500 | 转人工确认 |
| 每日累计 | $2,000 | 拒绝 + 通知 |
| 每周累计 | $10,000 | 拒绝 + 通知 |
| 总生命周期 | $50,000 | 永久冻结 |
| Gas 上限 | 0.02 ETH | 拒绝执行 |

### 可调用合约（Whitelist）

- Uniswap V3 Router ✅
- Uniswap V2 Router ✅
- 1inch Router v5 ✅
- USDC / WETH Token ✅
- 任意 approve() 非白名单 spender ❌
- transfer / transferFrom / multicall / permit ❌

### 可执行动作

| 动作 | 允许？ | 条件 |
|------|--------|------|
| swapExactTokensFor* | ✅ | 仅限白名单 router |
| swapExactETHFor* | ❌ | 不动用原生 ETH |
| approve | ⚠️ | 需人工确认 |
| transfer / transferFrom | ❌ | 防止直接转走 |
| multicall / permit | ❌ | 防止绕过检查 |

### 人工确认阈值

| 触发条件 | 阈值 |
|----------|------|
| 单笔金额 | > $200 |
| 滑点偏离 | > 1% |
| 连续失败 | ≥ 3 次/小时 |
| 新合约首次调用 | 任意 |
| 日累计接近上限 | > $1,500 (75%) |
| 非工作时间 | 22:00-08:00 |

### 撤销方式

1. Safe 面板一键撤销（即时生效）
2. 紧急冻结：发送"冻结 Agent"消息（30 秒生效）
3. 自动过期：Session Key 有效期 7 天
4. 额度耗尽：自动拒绝
5. Guardian 多签撤销：2 个 Guardian 中任意一个可冻结

### 日志记录

每条交易记录含：tx_id, timestamp, agent_id, session_key_id, action, tokens, amounts, expected/actual output, slippage, gas, policy_check, confirm_mode, tx_status（共 16 字段）

存储：链下 PostgreSQL + 每日 Merkle root 上链

### 失败处理

| 失败场景 | 自动处理 | 人工介入条件 |
|----------|---------|-------------|
| tx revert | 解析原因，分类处理 | 连续 3 次通知 |
| 滑点超标 | 取消，等待更好价格 | 连续出现通知 |
| Gas 过高 | 等待下降重试 | > 30min 通知 |
| 余额不足 | 跳过通知充值 | — |
| 合约暂停 | 切换备用 DEX | 通知 |
| Sandwich Attack | 标记，拉黑 builder | 通知复盘 |

设计原则：**Fail-Closed**（不确定就拒绝）、**Graceful Degradation**（单点故障不致命）、**User Sovereignty**（用户始终保留最终控制权）

## Task 3: ERC-4337、Safe、Guard/Policy 为什么重要

### 三层风险 → 三种解决方案

```
风险层 1: 私钥泄露（万能钥匙）
  → Safe 多签钱包：Agent 只有 session key，不是主私钥

风险层 2: 无限制执行（什么都能做）
  → Guard/Policy Engine：每笔交易经确定性规则校验

风险层 3: 账户不可编程（全有或全无）
  → ERC-4337：Smart Account 支持模块化权限、批量操作、Paymaster
```

### 各自解决的问题

**ERC-4337**：账户抽象 → 让 Agent 权限从「提示词里写规则」变成「链上合约强制执行」。UserOperation → Bundler → EntryPoint → Smart Account 校验的流程确保每一跳都有链上验证。

**Safe**：多签 + Guard 框架 → 高价值资产不依赖单一签名者。Guard 的 `checkTransaction()` 和 `checkAfterExecution()` 是交易执行前后的不可绕过钩子。

**Guard/Policy Engine**：确定性规则层 → LLM 不可预测（幻觉、注入、上下文污染），但 Guard 是硬编码/合约逻辑，不会出错。**Fail-Closed** 是核心原则。

### 完整安全架构

```
AI Agent（不可预测）→ Policy Engine（确定性规则）
  → Session Key（受限签名）→ Safe Guard（链上检查）
    → Smart Account（ERC-4337 校验）→ Bundler → 链上执行
```

每一层都可以独立拒绝交易，任何一层失败交易直接终止。

### 一句话总结

ERC-4337 提供可编程账户，Safe 提供多签+Guard 执行框架，Policy Engine 提供确定性规则约束——三者组合，AI Agent 才能从「只能聊天」进化到「安全操作链上资产」。

---

## 关键收获

1. 执行流程中，确定性规则检查（Policy Engine/Guard）必须是自动化且不可绕过的
2. 人工确认点的设计是「用确定性规则拦住明确不该发生的，用人工确认处理规则覆盖不了的灰区」
3. ERC-4337/Safe/Guard 三层解决的问题不同但互补：可编程性、多签安全、规则执行
4. Agent Wallet 权限策略的核心原则：**Fail-Closed、最小权限、用户主权、可审计、可撤销**
