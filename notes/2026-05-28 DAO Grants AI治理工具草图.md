## Task 1: DAO Grants 全流程拆解 — AI vs 人 vs 治理

场景：社区 Grants DAO（类似 LXDAO / Optimism RetroPGF / Gitcoin Grants）

```
═══════════════════════════════════════════════════════════════════
图例：🤖=AI自动  🤖→👤=AI草稿+人确认  👤=纯人工  🗳️=治理流程
═══════════════════════════════════════════════════════════════════

阶段 1: 📝 提案提交
  🤖 格式完整性检查、预算区间对比、历史提案关联、编号+标签
  🤖→👤 AI 生成摘要 → 申请人确认 / 相似提案提示
  👤 填写核心内容、签名提交

阶段 2: 📋 社区讨论（×天）
  🤖 提取关键问题、情绪倾向标注、追踪回复率、每24h汇总
  🤖→👤 讨论→修改建议清单 / 争议信号检测
  👤 提出问题、修改提案、社区回应

阶段 3: 🗳️ 投票
  🤖 终版摘要生成、参与率追踪、结果统计+可视化
  🗳️ 投票本身（Snapshot/Governor合约）+ 通过阈值校验
  👤 成员行使投票权

阶段 4: 💰 拨款执行
  🤖 生成多签交易 calldata、核对收款地址、里程碑付款计划
  🤖→👤 多签提案 + 付款解释 → 多签持有者审核
  🗳️ 多签确认（m/n）+ Timelock 延迟执行
  👤 多签持有者逐个签名

阶段 5: 🔨 交付与验收
  🤖 解析交付物（PR链接/合约地址/文档URL）、检查活跃度、标记异常
  🤖→👤 验收检查清单 → 审核人逐项确认
  👤 阅读代码/文档、评估质量、决定通过/修改/拒绝

阶段 6: 📊 贡献追踪与声誉
  🤖 聚合贡献数据（GitHub+链上+提案）、生成贡献者画像、排行榜
  🤖→👤 AI 建议声誉评分 → 管理员审核
  👤 确认并发布声誉更新

阶段 7: 💸 预算复盘与审计
  🤖 汇总拨款+支出、预算vs实际对比、财务仪表盘
  🤖→👤 下期预算建议 → 财务多签审核
  🗳️ 季度/年度预算经治理投票
  👤 审计异常交易
```

## Task 2: 三个工具草图

### 工具 1: Proposal Summarizer（提案摘要器）

```
输入：提案全文 → 输出：结构化摘要

🤖 AI 自动生成：
  📌 一句话摘要（≤80字）
  📊 结构化解析：金额、申请人、周期、类别、里程碑
  🔍 相似提案检测（含相似度 %）
  📋 完整性检查（✅/⚠️/❌）
  💬 讨论关键词预提取

⚠️ AI 推断标记（仅 AI 总结，非事实）：
  ⚠️ 申请人能力评估 → 统计推断，不替代审查
  ⚠️ 预算合理性 → 统计对比，不替代人工判断
  ⚠️ 风险信号（历史延迟等）→ 数据标记，社区自行决定权重

👤 需要人工确认：
  👤 摘要是否准确表达原意（申请人/管理员确认）
  👤 相似性判断（由作者回应差异 + 社区讨论）
  👤 预算最终审定（财务多签）
```

### 工具 2: Meeting-to-Action Workflow（会议→行动工作流）

```
输入：会议转录 → 输出：行动项 + 决策记录

流程：
  转录 → 🤖 清洗+结构化
       → 🤖 提取：概要+共识点+分歧点
       → 🤖 提取：行动项（负责人/任务/截止/来源发言）
       → 🤖 提取：决策记录（类型：共识 / 需投票）
       → 👤 主持人确认总结准确性
       → 👤 负责人确认/拒绝/转交任务
       → 🗳️ 共识项→多签执行 / 分歧项→Snapshot投票

每条输出必须标注来源标记：
  🤖[AI总结] = 来自 AI 对内容总结，未经核验
  🤖[AI推断] = AI 推断的结论（负责人、截止日等）
  👤[已确认] = 已由相关人员确认
  🗳️[治理通过] = 已通过 Snapshot/多签/Timelock
```

### 工具 3: Contribution Tracker（贡献追踪器）

```
数据源：GitHub + 链上 + 提案记录 + 讨论参与

🤖 AI 自动生成：
  📊 贡献者画像：提案数/通过率/拨款/交付率/GitHub活跃度/链上活跃/社区参与
  📈 社区健康仪表盘：活跃贡献者/新提案/通过率/交付周期/资金消耗率

⚠️ AI 推断标记（非事实，需人工判断）：
  ⚠️ 贡献者等级推断 → 统计标签，不自动赋权
  ⚠️ 风险信号（连续延迟等）→ 历史数据标记
  ⚠️ 活跃度下降 → 趋势标记，不是决策

👤 需要人工确认：
  👤 贡献者等级认定 → 管理员最终确认
  👤 声誉代币/POAP发放 → 手动触发
  🗳️ 贡献者等级与权限绑定 → 须经治理投票
```

## Task 3: AI 结论 vs 人工/治理确认 — 完整边界表

| AI 可以（processor/advisor） | AI 不可以（decider/executor） |
|---|---|
| 🤖 总结提案内容 | 👤 判断提案价值 |
| 🤖 提取讨论中的问题 | 👤 评估回答质量 |
| 🤖 计算投票统计 | 👤 解释投票原因 |
| 🤖 生成付款 calldata | 🗳️ 批准付款 |
| 🤖 检查交付物存在性 | 👤 判断交付质量 |
| 🤖 标记交付异常 | 👤 决定拒绝/要求修改 |
| 🤖 聚合贡献数据 | 👤 评定贡献者等级 |
| 🤖 标记趋势变化 | 👤 制定应对策略 |
| 🤖 对比预算 vs 实际 | 🗳️ 批准预算调整 |
| 🤖 生成摘要（conclusion） | 👤 做出决策（decision） |
| 🤖 标注相似提案 | 👤 判定是否重复/抄袭 |
| 🤖 建议行动项负责人 | 👤 分配任务 |

### 压倒规则

> **任何涉及资金转移、权限变更、声誉评级、或对提案的"批准/拒绝"结论，AI 只能生成建议草稿，最终必须由人或治理流程确认。AI 绝不能成为 DAO 治理流程中的最后一个签字人。**

---

## 关键收获

1. AI 在 DAO 中的正确角色是 **信息处理者 + 建议者**，不是决策者
2. 七个阶段中，AI 完全自动化的只有数据聚合和格式检查；实质判断永远在人
3. 每条 AI 输出必须标注来源（AI总结/AI推断/已确认/治理通过），防止AI结论被误认为事实
4. 三个工具的共性是：AI 降噪（提取、聚合、对比）→ 人决策（判断、批准）
5. 资金、权限、声誉的最终裁决权必须留在治理流程中（投票、多签、Timelock）
