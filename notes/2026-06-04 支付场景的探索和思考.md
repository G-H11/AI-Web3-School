## 一、核心观点：Agent 权限阶梯

Sky 提出 Agent 正在逐步进入"权限阶梯"（Permission Ladder）：

| 层级 | 内容 | 状态 |
|------|------|------|
| L1 代码访问 | Agent 读写文件、管理代码仓库 | ✅ 已广泛使用（Claude Code、Cursor 等） |
| L2 环境资产 | Agent 操作整台电脑、AWS 资源 | ⚠️ 探索中（rm -rf 事故频发） |
| L3 金融访问 | Agent 自主支付、管理资金 | 🔴 几乎未被解决，风险极高 |

> "rm -rf 删掉整个银行账户" → 资金场景容错率极低，不能像代码那样 build-test-fix 循环。

关键洞察：**编码有反馈循环（lint → build → test → fix），但金融没有——错了钱就没了，无法回滚。**

## 二、Flux 解决方案：Financial Harness（金融缰绳）

### 2.1 Mandate（授权声明）

**核心创新**：用户授权的是"任务"而非"单笔支付"。

- Mandate = 意图约束（Intent-based Constraint）
- 用户设定：任务目标 + 预算上限（如"订 A→B 机票，<$1000"）
- Agent 在沙箱内执行，所有下游交易必须遵守 Mandate
- 对比传统模式：不必每次 API 调用都弹窗确认，减少摩擦

### 2.2 三层验证引擎

```
Layer 1: Rule-based Filtering（规则过滤）—— 最快
├── 黑名单/白名单地址
├── 明显偏离 Mandate 范围的交易（订机票→买咖啡？）
├── 重复/循环交易检测（防薅羊毛攻击）
└── 错误率可控

Layer 2: Intent Matching（意图匹配）—— 语义层
├── 将支付信息与 Mandate 自然语言做语义一致性比对
├── 检查消费路径合理性（已订酒店→又订一个？）
└── Agent 的活动轨迹回溯到 Mandate

Layer 3: Model Evaluation（模型评估）—— AI 判官
├── 前两层无法判断时，交给独立 Agent 评估
├── Flag → 确认有问题；Pass → 人工最终审查
└── 自有 Benchmark + x402 社区数据验证，效果很好
```

三层递进：**规则（毫秒）→ 语义匹配（秒）→ AI 评估（秒-分）**，兼顾速度与安全。

## 六、与 SafeAgent Wallet 的关联

| Flux 设计 | SafeAgent Wallet 对应 |
|-----------|----------------------|
| Mandate（意图约束） | Policy Engine — 预算规则 / 白名单规则 |
| 三层验证引擎 | Policy Engine — 四规则 + 审计日志 + 五层验证 |
| Rule-based Filtering | 函数规则 / 白名单（Policy Engine 内置） |
| Intent Matching | 累积规则 / 上下文异常检测（待实现） |
| Model Evaluation | 五层验证的 AI 判官层（待实现） |
| Mandate 时间约束 | Policy Engine — 时间锁规则（待实现） |

**启示**：Flux 的 Mandate 模式与 SafeAgent Wallet 的 Policy Engine 理念高度一致——都是"先约束后执行"而非"执行后再补救"。SafeAgent Wallet 可以借鉴 Mandate 的"意图级别授权"设计，将 Policy 从纯参数约束扩展到语义层。
