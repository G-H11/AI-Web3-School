# EOA vs 智能账户 vs 多签账户 —— 权限与安全边界对比

> 日期：2026-05-27
> 来源：AI × Web3 School · Week 2 学习笔记

以下从**控制权、交易发起、多人确认、恢复/限额/自动化、适用场景、风险点、人工确认要求**七个维度展开。

---

## 一、总览对比表

| 维度 | **EOA** | **智能账户（Smart Account）** | **多签账户（Multisig）** |
|------|---------|-------------------------------|--------------------------|
| **谁持有控制权** | 私钥持有者独占 | 合约逻辑 + 可配置的所有者 | 多个签名者按阈值共同控制 |
| **谁能发起交易** | 私钥持有者直接签名 | 任何人可提交 UserOp；由合约验证 | 任一签名者可提交；需达阈值才执行 |
| **多人确认** | ❌ 不支持 | ✅ 可通过模块实现 | ✅ 天然支持 M-of-N |
| **恢复机制** | ❌ 无私钥即永久丢失 | ✅ 社交恢复 / 监护人 / 时间锁 | ⚠️ 需足够签名者存活 |
| **限额策略** | ❌ 无 | ✅ 可编程（日限额、白名单） | ⚠️ 需额外合约逻辑 |
| **自动化** | ❌ 每次需签名 | ✅ 支持 session key / paymaster | ❌ 每次需多人签名 |
| **典型场景** | 个人热钱包、交易 | 普通用户日常钱包、AA 应用 | 团队金库、DAO 财库、协议治理 |
| **Gas 支付** | 必须持有 ETH/原生代币 | ✅ 可用 ERC-20 代付 / 无 Gas | 必须持有 ETH/原生代币 |
| **主要风险** | 私钥泄露 = 资产全丢 | 合约漏洞 / 升级风险 | 签名者串谋 / 私钥丢失导致僵死 |

## 二、逐类详析

### 1. EOA（Externally Owned Account，外部拥有账户）

**本质**：一个公私钥对。谁有私钥，谁就完全控制这个账户。

**控制权**
- 私钥 = 绝对控制权。无私钥，无控制。
- 不依赖任何链上合约，链下签名即可操作。

**交易发起**
- 私钥持有者用钱包（MetaMask 等）对交易签名后广播。
- **一笔签名 = 一笔交易**，无中间层。

**关键特征**
- **不支持多人确认**：一人说了算。
- **不支持恢复**：私钥丢失 → 资产永久锁定。没有"忘记密码"。
- **不支持限额或自动化**：每笔交易都必须手动签名，无法设置日限额。

**典型场景**
- 个人日常使用的热钱包（少量资金，频繁交互 DApp）。
- 交易员高频操作。
- 作为多签或智能账户的**签名者/所有者**之一。

**主要风险点**

| 风险 | 说明 |
|------|------|
| 🔴 **私钥泄露** | 钓鱼网站、恶意合约授权、助记词被窃 → 攻击者直接转走所有资产 |
| 🔴 **私钥丢失** | 无任何恢复手段，资产永久不可访问 |
| 🟡 **单点故障** | 一个人出事（意外、失联），资产即失控 |

> **人工确认**：每笔交易都必须人工签名确认，无法自动化。

---

### 2. 智能账户（Smart Account / 合约钱包）

**本质**：一个智能合约充当钱包，用代码定义"谁能花、怎么花、花多少"。ERC-4337 是当前主流标准。

**控制权**
- 控制权由**合约代码 + 可配置的所有者**共同定义。
- 所有者可以是一个或多个 EOA，也可以是另一个合约。

**交易发起**
- 用户提交 `UserOperation`（用户操作）到 bundler，由合约的 `validateUserOp` 函数验证合法性后执行。
- 签名方式不限于 ECDSA —— 可支持 Passkey、WebAuthn、生物识别等。

**关键特征**
- ✅ **支持多人确认**：通过模块实现（如 Safe 的模块系统）。
- ✅ **社交恢复**：指定若干个"监护人"，多数监护人同意即可更换所有者。
- ✅ **限额策略**：可设置日转账上限、白名单地址、大额交易时间锁。
- ✅ **自动化**：
  - **Session Key**：授权一个临时密钥在一定时间内自动签名（如游戏内频繁操作）。
  - **Paymaster**：让第三方代付 Gas，用户可用 USDC 等 ERC-20 支付。
- ✅ **批量交易**：一笔 UserOp 包含多个操作（approve + swap + transfer）。

**典型场景**

| 场景 | 说明 |
|------|------|
| 普通用户日常钱包 | 免记助记词，用 Passkey / 手机生物识别 |
| 游戏 / 社交 DApp | Session Key 免频繁弹窗确认 |
| 企业支出管理 | 日限额 + 多级审批 |
| 新手 onboarding | 无需先买 ETH 付 Gas |

**主要风险点**

| 风险 | 说明 |
|------|------|
| 🔴 **合约漏洞** | 钱包合约有 bug → 所有用户资产受损（如 Parity 多签漏洞事件） |
| 🟡 **升级风险** | 若合约可升级，升级被劫持可能导致资产被盗 |
| 🟡 **模块风险** | 第三方模块（恢复模块、session key 模块）若有漏洞，可被绕过 |
| 🟡 **Bundler/Paymaster 中心化** | 依赖 bundler 网络，若 bundler 审查交易，用户无法操作 |
| 🟢 **私钥丢失** | 有恢复机制 → 影响远小于 EOA |

> **人工确认**：
> - 添加/更换**所有者**：必须人工确认。
> - 修改**限额**：必须人工确认。
> - 添加**监护人**：必须人工确认。
> - **Session Key 内的小额操作**：可自动执行，无需人工确认。
> - **日限额内的转账**：可自动执行。

### 3. 多签账户（Multisig Wallet）

**本质**：N 个签名者中至少 M 个签名，交易才能执行。最常见的是 Safe（原 Gnosis Safe）。

**控制权**
- 控制权由**M-of-N 阈值**定义。
- 例如 3-of-5：5 个签名者中至少 3 人同意，才能动用资金。
- 任何单一签名者无法单独控制。

**交易发起**
- 任一签名者可**发起**交易提案。
- 交易进入**待确认队列**，其他签名者审核后签名。
- 达到 M 个签名后，**任一签名者**可执行该交易。

**关键特征**
- ✅ **多人确认**：天然支持，这是其核心价值。
- ⚠️ **恢复机制**：取决于签名者是否存活。若太多签名者丢失私钥导致无法达到阈值 → 资产永久锁定。
- ⚠️ **限额策略**：不内置，但可通过合约模块或治理流程实现。
- ❌ **自动化**：每次都需要多人签名，无法自动执行日常操作。

**典型场景**

| 场景 | 说明 | 典型配置 |
|------|------|----------|
| DAO 财库 | 社区投票后由多签委员会执行 | 4-of-7 或 5-of-9 |
| 协议升级 | 治理通过后多签部署新合约 | 3-of-5 |
| 团队金库 | CTO + CFO + CEO 联合管理 | 2-of-3 |
| 个人冷存储 | 2-of-3（手机 + 硬件钱包 + 纸质备份） | 2-of-3 |

**主要风险点**

| 风险 | 说明 |
|------|------|
| 🔴 **签名者串谋** | 若 M 个签名者勾结，可绕过其他签名者转移资产 |
| 🟡 **阈值僵死** | 签名者丢失私钥过多，无法达到 M → 资产永久锁定（如 2-of-3 中 2 人丢失私钥） |
| 🟡 **社会工程攻击** | 攻击者伪装成团队成员请求签名 |
| 🟡 **签名疲劳** | 高频操作时签名者"随手签"，降低安全性 |

> **人工确认**：
> - **每笔交易**都需 M 个签名者各自人工审核并签名。
> - 即使达到阈值，执行者也需**确认执行**（尤其大额交易）。
> - 修改签名者集合或阈值：必须当前多数签名者人工确认。

## 三、三类账户的递进关系

```
EOA（最基础）
  │
  ├─ 做成多签的所有者 ──→ 多签账户（共享控制）
  │
  └─ 成为智能账户的所有者 ──→ 智能账户（可编程控制）
        │
        └─ 设置多个所有者 ──→ 智能账户 + 多签（最强组合）
```

**最强组合**：Safe 这样的智能合约多签钱包，既有多签的**共享控制**，又有智能账户的**可编程性**（模块、恢复、限额）。

---

## 四、一句话总结

| 账户类型 | 一句话 |
|----------|--------|
| **EOA** | 私钥即一切 —— 最自由也最脆弱 |
| **智能账户** | 钱包变成可编程的应用 —— 最灵活 |
| **多签账户** | 没有人能独断专行 —— 最安全（共享控制） |

---

## 五、选型建议

| 你是谁 | 推荐 |
|--------|------|
| 个人用户，资金少，频繁交互 | **EOA**（热钱包）+ 备一个多签冷钱包存放大额 |
| 个人用户，资金多，想省心 | **智能账户** + 社交恢复 + 2-of-3 多签做恢复守护者 |
| 团队金库 / DAO 财库 | **多签账户**（Safe），M 不低于 N/2+1 |
| 产品要面向普通用户 | **智能账户**，免 Gas、免助记词，session key 提效 |
