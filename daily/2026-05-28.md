## 学习笔记

<!-- 今日学习要点、疑问、心得 -->

### 关键概念

- **Agent Profile 七维度**：Identity / Capability / IO / 协作对象 / 收费 / 验证 / 失败处理
- **MCP vs A2A**：MCP 解决 Agent ↔ Tool 接口标准化（单向、无状态），A2A 解决 Agent ↔ Agent 协作标准化（双向、有状态、Task 追踪）
- **ERC-8004**：补充身份与信任层——Agent 链上注册、声誉评分、可插拔验证
- **ERC-4337 / Safe / Guard 三层架构**：
  - ERC-4337：账户抽象，让 Smart Account 替代 EOA，权限约束从提示词变成链上合约
  - Safe：多签 + Guard 框架，高价值资产不依赖单一签名者
  - Guard/Policy Engine：确定性规则层，AI 不可预测但 Guard 硬编码不会出错
- **Agent Wallet 权限策略七维度**：预算 / 可调用合约 / 可执行动作 / 人工确认阈值 / 撤销 / 日志 / 失败处理
- **核心原则**：Fail-Closed（不确定就拒绝）、最小权限、用户主权、可审计可撤销
- **Threat Model 六维度**：资产 / 权限 / 数据 / 工具调用 / 外部依赖 / 失败后果，每个维度覆盖攻击面+最坏后果+防御
- **风险分级公式**：风险分数 = 金额 × 操作 × 上下文 × 新鲜度（各 1-5 分），乘积映射四档：🟢自动/🟡通知/🟠暂停/🔴冻结
- **攻击模拟关键发现**：AI 层拦截率 0%；Policy Engine 90% 覆盖率；Oracle 投毒是唯一穿透所有层的攻击；多源价格验证是最薄弱环节
- **DAO Governance AI 四阶标记体系**：🤖AI自动 / 🤖→👤AI草稿+人确认 / 👤纯人工 / 🗳️治理流程（投票/多签/Timelock）
- **AI 角色边界**：信息处理者 + 建议者，不是决策者。资金转移、权限变更、声誉评级的最后签字人永远是人或治理流程
