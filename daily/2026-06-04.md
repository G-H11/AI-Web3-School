## 学习笔记

<!-- 今日学习要点、疑问、心得 -->

### 关键概念

1. **Agent 权限阶梯**（Permission Ladder）：代码访问 → 环境资产 → 金融访问。金融层几乎未被解决，因为"rm -rf 删掉整个银行账户"的容错率为零。

2. **Mandate 模式**：用户授权"任务"而非"单笔支付"——设定目标 + 预算上限，Agent 在沙箱内自由执行。这比每次弹窗确认高效得多。

3. **三层验证引擎**：规则过滤（毫秒，黑白名单/范围检测）→ 意图匹配（秒，语义一致性检查）→ AI 判官（秒-分，独立 Agent 评估边缘案例）。三层递进，兼顾速度与安全。

4. **编码 vs 金融反馈循环差异**：编码有 build → test → fix 循环，但金融"pay then check then fail"无法回滚，必须在支付前完成所有验证。

5. **与 SafeAgent Wallet 的映射**：Flux Mandate ≈ Policy Engine 预算规则；三层验证 ≈ Policy Engine 四规则 + 五层验证；Mandate 时间约束 ≈ 时间锁规则。两个方案核心理念一致——"先约束后执行"。

### 遇到的问题

- MVP 编码任务未启动：今日时间投入偏向会议和关联分析，`demos/safeagent-wallet/` 尚未初始化
- Cobo SDK 三个待确认问题仍未解决
- Hackathon NFT DApp 开发时遭遇 Git clone 子模块 TLS 失败（代理问题），通过环境变量 HTTPS_PROXY 解决；yarn link 步骤因 WSL F: 盘 I/O 慢导致超时但实际已安装

### 解决方案 / 理解

- 将 Flux Mandate 模式作为 SafeAgent Wallet 的参考设计——特别是"意图级授权"而非参数级约束
- 三层验证引擎的分层思想可融入 Policy Engine 设计：规则层（毫秒判断）+ 语义层（AI 辅助）+ 人工兜底
